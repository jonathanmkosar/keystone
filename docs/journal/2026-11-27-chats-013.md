## What was learned

- The router's Facts want the call's size before the call exists. Estimating the branch and the message is cheap and close; the budget still checks the real call, so the worst case is a refused call that the chain moves past, not an oversize one sent.
- Taken as written, rule 2 would refuse a picture on any ladder without a vision model, and every message on a ladder whose models take no tools, where a picked model answers both. A need nobody on the ladder can meet is now dropped, and the uploads code leaves the image out with its notice as before.
- A route event on every turn would have changed the stream of every chat, and nine existing tests compare streams exactly. Sending it only on Auto kept them all, and the turn event already names the model.
- The browser's choice is parsed field by field in `api.ts` (`chatModel`, `inspectTurn`), so new fields from the server are dropped until the parser names them. The first look in the browser showed the server answering `auto: true` and the chip still naming the model; the fix was two parsers, and the lesson is to look at the page, not only the route.
- `preview_start` reads only the main checkout's `.claude/launch.json`, which a worktree agent must not write. The server was started from the worktree by hand on its own port, and the pane opened at its address.
- A held chat's verdict that names the hosted step is not even a valid answer there: the hosted step is not among the options, so `seam.ValidateDecisionResult` refuses it and the rules decide. The proof checks both what was offered and what was called.
