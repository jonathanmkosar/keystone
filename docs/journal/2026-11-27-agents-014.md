## What was learned

- **Edge on Windows drives over a pipe with no port.** `--remote-debugging-pipe` with `--remote-debugging-io-pipes=<in>,<out>` and Go's `AdditionalInheritedHandles` works against Edge 158; the browser writes no `DevToolsActivePort` file. Tried in a spike before the plan.
- **`Fetch.enable` on the browser target pauses everything**, frames and the browser's own component extensions included, so one policy holds every rule. Without it, a frame or a popup is a target of its own that a tab's interception does not see.
- **A failed page shows an error page; an aborted one does not.** The planted page's own form, sent on a timer after the open had returned, first replaced the page with Edge's "blocked" page, so the next read read that. Refusing a page as `Aborted` keeps the page the agent was reading.
- **A fresh headless profile was not signed in to an account.** Edge's and Chrome's `Local State` and `Preferences` held no account and no address after eight seconds, with and without the hardening switches; the switches stay.
- **A click with the switch off asked the person** before the tool refused it, because the approval policy decides before a tool runs. The check found it (the recorded turn never ended); such a call is now refused without asking.
- **A step's calls are in the record before any runs**, so a turn's browser calls and pages can be counted from the chat itself, and the count holds after a restart.
- The fake browser's first page panicked on an empty history while it held its lock, and `tools.Run`'s recover left the lock held; the next close hung. Fixed in the fake; the pool's own locks are released by `defer`.

The item's proof:

- **The profile holds no cookies from the person's browsers** (`TestTheProfileHoldsNoCookiesButItsOwn`, `TestARealBrowserKeepsTheRules`, and the check): no cookie at start, a page's own cookie for its own host only, a cookie for another site closes the browser, and a profile with a cookie at start is never used. The profile is `browser-profile` in the person's tenant folder, fresh at each start, and gone at close and after the idle time.
- **A page with planted instructions cannot cause an unapproved side effect** (`TestAPlantedPageCannotCauseAnUnapprovedSideEffect`, `TestARealBrowserKeepsTheRules`, `TestAPlantedPageCannotCauseAnUnapprovedSideEffectInATurn`, and the check on the real server): with Edge, the planted page submits its form on a timer, posts with `fetch` and loads a frame that posts, and the server on this machine received nothing; its text is marked as outside content; the click on its button with no approval is refused by the tool loop; in a turn the click asks with the reason `outside` even with the person's policy for it set to always, nothing is sent while it waits, and declined it is never sent; approved, the form is sent once.
- **A password field is refused**, with Edge and the fake: a password, a sign-in form's email, a sign-in button and a card number; on the real server a password is not typed even when the person approves the call.
- Also: a download refused with nothing saved; blocked hosts, links to them, `javascript:` and `file:` addresses, this machine and the home network refused; off unless switched on, and not offered then; off in a held chat; one chat cannot read another's page; every call in the audit log; a screenshot served to its person only and gone with its chat; a turn's pages and steps counted.

Not run: the step rows and the screenshot under a step on a running server in a browser (they were type-checked only); a real site or the real web; a real model; any system but Windows; `go run ./tools/rebuild`; the race detector.

## Questions for the owner

- **Should a page be able to send with POST while the agent only reads?** As built, no (decision 0581): a site that reads with POST, as some search boxes and single-page apps do, shows less, and the result says what was stopped. Recommended: keep it, and add a per-site exception only if a site the owner uses needs one. Assumed meanwhile: no.
- **Should opening a page ask?** As built it does not, as `web_fetch` does not (decision 0585); a person can set `browser_open` to ask on Settings → Approvals. Recommended: keep it. Assumed meanwhile: it does not ask.
- **Should the model see the screenshots?** As built it reads the page's text and numbered elements, and the person sees the screenshots (decision 0584). Recommended: try it with text first, and send a screenshot to a model that can see only if pages built on a canvas matter. Assumed meanwhile: text only.
- **The shipped block list** holds the big sign-in and payment sites (Google, Microsoft and Apple sign-in, PayPal, Stripe checkout). Recommended: keep it, and add the owner's bank. Assumed meanwhile: as shipped.
