## What was done

- **`internal/research`**, a new package. A research task is a row in `research`, worked by a goroutine under the turn runner as a background task is, in three steps that Keystone's own code runs (decision 0520): a **plan** turn of a chat of the task's own ("Research: …"), whose reply is read as a list of parts, at most `agents.research_parts`; a **sub-agent for each part**, which searches with `web_search` and reads with `web_fetch`; and a **report** turn, written from the parts' findings and the numbered sources. When it ends, a note with the summary is written in the chat it was started from, and the report is saved there as a Markdown artifact. Five routes: `GET /research` (what a task would run with, so the budget is shown before it starts), `GET` and `POST /chats/{id}/research`, `GET /chats/{id}/research/{research}`, `POST …/stop`.
- **Sources and citations**, `internal/research/cite` and `report.go`. A source is an entry of a `web_search` or `web_fetch` result kept in a part's chat record, read with `web.Sources`; nothing a model writes adds one (decision 0521). The sources are numbered once across the parts, a page two parts read is one source, and each part's findings are rewritten to those numbers. `cite.Check` takes every citation that names no source out of the report, renumbers the rest in the order they appear, and the list of sources is written by Keystone. What was taken out is counted, on the task, in the report and in the note.
- **One budget** (decision 0522). `agents.research_budget_usd`, $3 as shipped, is the whole task's. The task's own run and each part are unattended runs; the task's run is lowered to `agents.research_report_share_percent` before the parts are given the rest in even shares, and raised by what they did not spend when they have ended, with the new `unattended.SetBudget`. At its budget a task stops with what it has and says so: a refused plan fails with `spend_cap`, a refused part ends with what it had, and a refused report is put together by Keystone from the findings.
- **The rules**. Marks go down into the task's chat and its parts' (`carry.Down`), so a held chat's research runs only on models that may read it and its web tools are off; a part that was sent sensitive content gives its findings only to a held task, and a held task started from a chat that is not held keeps its report in its own chat (`carry.Up`, decision 0524). The task's chat is marked as having read outside content before the report step, and the chat that gets the note before the report is saved there (decision 0525). No memory pass reads the task's chat. Stop, the pause switch and a restart each have their path; parts cut short are not run again (decision 0523).
- **`internal/subagents/direct.go`**, new: `Runner.StartParts`, `Parts` and `StopParts`, `Ended` and `ErrPaused`, for sub-agents that code starts. **`internal/unattended/budget.go`**, new: `SetBudget`.
- **The screen**: `web/app/src/Research.tsx`, `researchCalls.ts` and `research.css`. The Research control in both composers, the line that says what a task will run with, the card with the plan, a lane for each part and the sources found, and the note with its citations linked, the report's card and its sources. `web/dist/` is not committed.

## What was learned

- **`web_fetch` cannot be pointed at a stand-in from outside its own package**, and should not be: it reads only public addresses, and that check is the point of it. So a research task's sources in every end-to-end test are search results, and a fetched page as a source is checked on a chat record the test writes. A search result therefore counts as a source, and the report's list says when a source was read as an extract only.
- **The gate refuses a call on the most it could cost**, which for a model with a large reply limit is many times what a call does cost. A fixed share of the budget for the report would refuse it with most of the budget unspent, so what the parts leave goes back to the report step.
- **The order of the note and the artifact matters.** The note waits for a turn running in the chat it lands in. With the report saved first, that turn could read it with `read_artifact`, which marks nothing, and then change something without asking. So the note, which marks the chat with its queue held, is written first.
- **The test for the budget needed a part that costs a known amount.** Tuning a budget against the gate's estimate of a call was brittle; a part whose recorded usage costs five cents of six is not.
- The answer to Stop can already be the ended task, so nothing was following it when it ended: the cards now read the chat again whenever a task they saw under way has ended, however they learned of it.
- The fixture's recorded turns go by words of the shipped prompts. A changed prompt needs its recorded turn changed with it, which the `research mode` check says at once.

## Questions for the owner

- **A research task's budget**, `agents.research_budget_usd`, ships at $3, with 30% kept for the plan and the report and the rest split between up to four parts. Recommended: keep it, run one real research, and look at what each part spent before changing it. Assumed meanwhile: $3.
- **Should the chats a research task makes stay in the sidebar?** One task adds its own chat and one for each part. Recommended: keep them out of the sidebar and reach them from the card and the note, once the chat list can hide a chat, as recommended for sub-agent chats (agents 010). Assumed meanwhile: they stay.
- **Should a part that a pause or a restart cut short be run again?** Recommended: no, as built (decision 0523): the report says which part is missing, and the person asks again if they want it. Assumed meanwhile: not run again.
- **Should the question be written in the chat as the person's message?** As built it is on the card and in the note, and the chat's own record has only the note. Recommended: leave it until the mockups show where a research task sits in a conversation.
