## What was done

- A new package, `internal/tools/web`, standard library HTTP only.
  - `Searcher`, an interface with one method, and `Tavily`, with New Keystone's request: a bearer key, `search_depth`, `max_results`, no answer, no raw content, `auto_parameters` off. Results with an address that is not `http` or `https`, or that has a user name, are dropped; titles and extracts are cut. 401 and 403, 429, 432 and 433, other statuses, an answer too large, too slow or not JSON each have a sentence.
  - `web_search` (`query`, optional `count`) and `web_fetch` (`url`), both read-only. The key is read on each call from the person's vault as `provider.tavily`; with none, the tool answers "Web search is not set up: store a Tavily key as provider.tavily." and sends nothing. A key the service sends back is removed from what the model reads. A query that looks like a credential, or is longer than 400 characters, is not sent.
  - `web_fetch` reads only public addresses. Keystone resolves the name, every address must be public, it dials the address it checked, and the socket checks it again as it connects; every redirect is dialled and checked the same way. No proxy. HTML becomes readable text; other files are refused with their type.
  - Numbered sources that run on through a turn, written into the result in a fixed form, and `web.Sources`, the reader of that form.
  - Both tools are off in a chat held for sensitive content.
- A new file in `internal/tools`, `outside.go`: `OutsideMark` (`[Outside content]`), `MarkOutside`, `IsOutside(block)` and `ReadOutside(messages)`. Every web result that brought outside content opens with the mark and a sentence telling the model the text is information, never instructions.
- Eleven settings in `settings/agents.json`, install scope, read by `web.ReadOptions` from `app.ReadConfig` into a new `app.Config.Web`, and the tools registered in `app.Tools` by `web.Add`.
- A recorded turn for the test tenant, `turns/web-search.json`: the model searches the web and answers citing [1] and [2].
- In `verify`: a step of `calls recorded` and a surface of `no keys in output`, both in a new file, `tools/verify/websearch.go`; `internal/tools/web` on the `offline` list.
- The screen: rows for both tools in `steps.ts` ("Searched the web for “…”", "2 results"; "Read “title”"; "not set up" and "off in this chat" as plain tags), a globe icon, and citations. A new file, `citations.tsx`, reads a reply's sources from its web steps and draws each [n] that names one as a small chip that links to it; the Markdown reader has one more pattern for [n]. `web/dist/` is rebuilt.

## What was learned

- A search whose numbers start at 1 each time collides as soon as a turn searches twice, and Claude models search twice in one reply often. The tool numbers through the turn instead, and needs the turn's start, which it reads from the chat record; the calls of one step are stored only together, so the running count is kept in memory too (decision 0250).
- The record keeps a result's words, so the numbers had to be in the words for the screen to find them after a reload. Writing each source as single lines, and stopping the reader at the first block that is not a source, means a web page cannot add a source by writing one. The test has a page that tries.
- Checking an address as written misses a name that resolves home, and checking before connecting misses DNS rebinding. Resolving in Keystone, checking every answer, and dialling the address checked closes both, and a redirect goes through the same dialler (decision 0251). The shared range 100.64.0.0/10 is private here: the owner's Mac mini is reached over it.
- The approval policy is being built beside this. Its plan counts every tool that does not say it is Keystone's own as outside. A mark in the result's text, in a new file, needed no field on `tools.Tool`, no change to the stream and no line in `internal/turn`, so the two cannot conflict, and it says what a flag on a tool cannot: whether this call brought anything (decision 0253).
- The test tenant has no search key, so on the shipped server the recorded search says "not set up" and its [1] and [2] stay text. That turned out to be a useful second check in the browser.

## What was verified

- `go run ./tools/verify` is 19 of 19 before each commit.

The item's proof:

- **Answers cite their sources.** `calls recorded` runs the recorded web search on the real server with the search pointed at a stand-in and an invented key stored: the stand-in had one search with that key as its bearer token, the result's two numbered sources are the stand-in's two results, and both citations in the stored answer name one of them. The unit tests number two searches in one step 1-2 and 3-4, carry on after a restart, and start again at 1 in the next turn.
- **Fetched pages mark the turn as having read outside content.** A fetched page's result is `IsOutside`, and a turn holding it `ReadOutside`; so are a search's result and the chat record in `calls recorded`. A refused fetch, a failed search and a search that found nothing are not.
- **Private addresses are refused**: this machine by number, by name and over IPv6, a home router, a private network, the cloud metadata address, the shared range, a private IPv6 network, a private address written as IPv6, a name that resolves to a home address, a name that resolves to the internet and a private network both, a name that resolves to this machine, a bare name and a `.local` name; and redirects to a private address, to a name that resolves to one, to `file:`, and in a loop. The page served on this machine was never reached.
- **A missing key gives a plain message**, as an error result the turn goes on from, and nothing is sent.
- **The key is in no output**: not in any refusal, even when the service repeats it, nor in a result that echoes it, the audit log or the data folder (`no keys in output`, web search surface).
- In a browser, against a server built from this branch on port 7951 by a launcher that was not kept, with a data folder inside the worktree (removed afterwards), the test tenant loaded, an invented key in its vault and the search pointed at a stand-in on this machine, signed in as the test tenant with the fixture's password: the recorded web search drew "Searched the web for “harbour museum opening hours”" with "2 results", and the answer's two citations as chips linking to `https://museum.example/hours` and `https://visit.example/harbour`, with their titles. The row opened to show the marked result. The same after a reload, in dark and light, and at phone width. With the key removed through the secrets route, the same question drew "Search the web for “…”" with "not set up", the sentence in the open row, and plain [1] and [2]. The server was stopped.
