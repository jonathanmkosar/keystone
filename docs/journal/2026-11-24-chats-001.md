# Chats 001, 2026-11-24

Item done: P4-02, the chat record.

## What was done

- A new package, `internal/chat`: plain functions over one tenant's store. No routes, because there is no API yet.
- Chats: `Create`, `Get`, `List` (newest message first, a starred filter, a limit and an offset), `Rename`, `Star` and `Delete`.
- Messages as a tree: `Append`, `GetMessage`, `Path` and `Select`. An edit or a retry is a new message under the same parent. Each parent remembers its current child, and the current branch is the path that follows them. This is decision 0020.
- Content is a `seam.Message`, written with `seam.EncodeMessage` and read with `seam.DecodeMessage`.
- `Search` over titles and the words of text blocks, with SQLite's FTS5. A result names the chat and, for a message, the message.
- `AddFile` and `Files`. A file is tied to a chat by a row in `chat_files`, and `Append` adds the row for every file a message refers to.
- `Delete` removes the chat's rows, its search rows, and each of its files that no other chat holds.
- One migration, `20261124T213000_chat_record.sql`: `chats`, `messages`, `chat_files`, and the search tables `chat_title_search` and `message_search`.
- `settings/chats.json` with three settings: `chats.title_max_length`, `chats.search_max_results` and `chats.search_snippet_words`. The registry now holds six.
- The doc `docs/architecture/chat.md`, a row in the overview, a line in `verify`'s list of parts, and decision 0020.

## What was learned

- FTS5 is compiled into `modernc.org/sqlite` v1.63.0. A test asks SQLite itself, with `sqlite_compileoption_used`.
- An FTS5 row is found again by its `rowid`, so the rows it indexes need a number of their own. A message's id is that number. A chat keeps its random id and has a row number, `seq`, beside it.
- Deleting the chat's row removes its messages by `ON DELETE CASCADE`, although the messages point at each other and the chat points at one of them. SQLite checks foreign keys when the statement ends, and by then they are all gone.
- A table from a later item that names `chats(id)` with `ON DELETE CASCADE` loses its rows when the chat is deleted. A test makes such a table and checks it.
- Files are removed before the transaction commits, not after. If one will not go, the chat stays and the delete can be run again. The other order could leave a file that nothing names.
- Stepping back to a branch point lands on the child that was last chosen there, which is not always the newest one. The first draft of the test expected the newest and was wrong.
- A message appended under a parent that is off the current branch does not move the current branch. That is what a reply needs when it arrives after the person has stepped away.
- The first form of `Select` set each pointer with a subquery and took about 10 milliseconds on a chat 600 deep. Written as `UPDATE ... FROM` it took about 3, and about 14 at 3,000 deep. Reading the path took about 3 milliseconds at 600 and about 20 at 3,000. These were timed once, with a test that was not kept.
- Words typed into search are each put in quotes before FTS5 sees them. Without that, a stray quote or a word such as `NOT` is a syntax error.

## What was verified

On Windows 11 with Go 1.26.0, in the worktree for this item:

- `gofmt -l .` prints nothing and `go vet ./...` is clean.
- `go test ./...` passes. The chat tests cover 86.2% of the package's statements.
- `go run ./tools/verify` is 8 of 8.
- `go run ./tools/rebuild` is green: 6 settings, the page served over HTTP, a data folder with no tenants, `verify` 8 of 8.

The tests cover the item's proof. Edit and retry make branches, the branches are walked back and forth, and each side reads as it was left. A deleted chat leaves no row, no search row and no file, while the other chat's rows and files, a file both chats held, and a file no chat was tied to are untouched. Two tenants' chats and search results never mix, and deleting in one tenant leaves the other's file of the same name alone.

Run once by hand and not kept as a test: a database that had not seen the chat migration was opened, got the migration, and took a chat, a message and a search.
