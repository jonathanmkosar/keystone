## What was done

`rebuild`, `verify`, `doctor` and `snapshot` under `tools/`, with shared helpers in `internal/project`. An overview and a doc for each part under `docs/architecture/`.

## What was learned

- `doctor` reads the item files, so it can say which item each lane may pick up next. That is what a lane's agent needs at the start of a loop.
- `verify` checks the plan itself: a dependency on an item that does not exist, or a loop, turns it red.
- The Go module proxy could not be reached from the workspace this loop ran in. P0-01 and P0-02 need no outside modules, so nothing was blocked. P2-01 needs `modernc.org/sqlite`, so it must run where modules can be downloaded, such as the owner's Windows machine.

## What was verified

On Linux with Go 1.24.7: `go run ./tools/rebuild` green, `go run ./tools/verify` 8 of 8, rebuild run twice with the same snapshot. A planted key and a dependency on a missing item each turned verify red, and removing them turned it green again.
