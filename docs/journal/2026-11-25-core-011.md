The owner uses hosted models daily under a $100 monthly cap, and until now the only way to see where the money went was `tools/tenant usage`, by model, for a month. This pass made the report a person reads in Settings: a period's spend against the cap, by model, by chat and by kind of work, summed from the usage records so it cannot drift from them.

## What was done

- A new package, `internal/usagereport`. `Read(ctx, store, registry, ask, now)` is the one function behind the new route and the command line. `Resolve` turns an ask (a named period, a month, or a range of days) into calendar days in UTC; `Records` reads the period's records with `usage.List`; `Summarise` sums them in one pass into a total and three breakdowns, each line with calls, input, output, cache read and cache write tokens and cost, split into local, hosted and trusted; a breakdown shows `usage.report_rows` lines, costliest first, and adds up the rest in one more line. The cap is read with `usage.Spent` and the reserve with `usage.SpentOn`, as the gates read them.
- Placing a record (decision 0430): a usage record names no chat and no task, only the request id of the API call that set it off. The report finds the background task with that request id (a scheduled task when a schedule run started it, and its work chat), else the turn sent under it, else the chat in the path of the API call in the audit log; a chat that is gone, or none, is the line "Not in a chat you still have". A migration, `20261125T222300_usage_report.sql`, indexes `turns(request_id, seq)` for it.
- The route `GET /api/v1/usage`, with `period`, `month`, `from` and `to`, and `rows`; refusals `bad_period` and `bad_request`. Added in `internal/app/app.go` with one line. The OpenAPI document is regenerated.
- `tools/tenant usage` rewritten on `Read`: a month, a range of two days, or a named period, printing the tables by model, by kind of work and by chat, the split by class, the cap and the reserve.
- Settings → Usage at `/settings/usage`, in place of the Spend placeholder (`/settings/spend` goes there): the month against the cap as a bar with the warning threshold marked, the memory reserve, a period picker, the totals, and the three breakdowns as tables with a small bar on each line and a chat's name linked to the chat. Bars are inline SVG from the tokens (decision 0432). New files `UsageSettings.tsx`, `usageCalls.ts`, `usage.css`.
- Three settings in `settings/core.json`: `usage.report_period` (tenant, `this_month`), `usage.report_rows` (tenant, 10), `usage.report_max_days` (install, 366).
- The standing check `usage report`, in `tools/verify/usagereport.go`, makes `verify` 27 of 27.
- Docs: `docs/architecture/usage-report.md`, decisions 0430 to 0432, rows in the overview and `internal/README.md`, paragraphs in `tools.md`, and lines in `usage.md` and `settings-screens.md`.

## What was learned

- The usage records already carry everything needed to place a call, through the request id: decision 0293 gave a task its own request id for its budget, and every summary, recap, title and memory call is made under its turn's. Reading the place out of the other tables changed nothing that writes a record, which mattered with two other lanes adding writers and readers of the same table.
- A task's note in the chat it was started from is a turn under the task's request id. Looking at turns first would have put a task's spend in the chat that started it; the task has to be looked for first.
- Compaction and recaps both record the kind `summary`, and the records hold nothing to tell them apart, so the report has one kind for both.
- A stored setting that is not a number is not "a cap that does not read": tenant settings fall back to the default for a value that no longer fits. Only a number that is not a cap, such as a negative one, is refused by `usage.NewCap`, and the gate then stops every paid call. The first test of the unreadable cap assumed otherwise and failed; it now stores `-5`.
- A month period loads only that month's records through the month index, so a fault that kept a range's first moment after went unseen until a record was put exactly there. The generated records now include one at that moment.
- The content security policy refuses a `style` attribute, so a bar's width cannot be a style. An SVG rectangle's width is an attribute, and the fill can be a class reading a token.
