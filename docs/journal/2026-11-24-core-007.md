# Core 007, 2026-11-24

Item done: P2-04, the audit log and per-tenant settings.

The lane's session built and committed the code, its docs and decisions 0009 and 0014 in its own worktree and then stopped. This entry was written by the integrator at the merge.

## What was done

- A new package, `internal/audit`. An `audit_log` table in each tenant's database that triggers keep append-only, a scrubber that removes keys, and `Wrap`, which records an API call before it runs and again when it ends.
- A new package, `internal/tenantsettings`. A tenant's own values over the registry's defaults, limited by each setting's scope.
- `settings/fixed.go` names the plan's four fixed rules. A key in their space cannot be a setting and cannot be stored as an override.
- Two migrations, `20261124T212000_audit.sql` and `20261124T212500_tenant_settings.sql`.
- A new standing check in `verify`, `fixed rules`, in `tools/verify/fixedrules.go`.
- Docs: `docs/architecture/audit.md`, `docs/architecture/tenant-settings.md`, rows in the overview, decisions 0009 and 0014, and the check in `tools.md`.

## What was learned

- The fixed rules check earned its place on its first merge. It refused P2-03's tenant package, which read a setting while guarding tenant isolation. See core 006.
- `internal/audit` imports `net/http` for its wrapper, and P3-03's offline check refuses a network import outside its list. The folder was added to the list with its reason: it wraps the server's handlers and opens no connection. The list exists for this, so the check was not loosened.
- "Every API call lands in the audit log" cannot be proven for routes that do not exist. What is proven is that a handler inside `Wrap` is never served without an entry. P2-05 puts every route inside it and adds the walk.

## What was verified

On Windows 11 with Go 1.26.0, on `reboot` after the merge:

- `gofmt -l` prints nothing, `go vet ./...` is clean, and `go test ./...` passes.
- `go run ./tools/verify`: 12 of 12, with `fixed rules` among them.
- The item's proof, in the packages' tests and the check: an override is stored and read back within its scope, and a fixed rule is refused from a person, from the admin, and as a row written straight into the database.

Not run: macOS and Linux.
