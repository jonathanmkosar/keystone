## What was done

- **`internal/mcp`**, a new package, standard library only: an MCP client for protocol version 2025-06-18, taking a server that answers 2025-03-26, or 2024-11-05 over stdio. `Connect` (initialize, the version check, `notifications/initialized`), `ListTools` with its cursor, `CallTool`, `notifications/cancelled` for a stopped call, `ping` answered, `tools/list_changed` noted. Two transports: `Stdio` (the command run directly with exactly the environment given, a line per message, a banner let go, the last 2 KB of standard error named with the token taken out, no console window on Windows) and `HTTP` (the streamable transport: POST, a JSON or event-stream answer, the session id and protocol version headers, DELETE at close, 404 as a forgotten session, 401 and 403 refused without reading the body, no redirect, an error that never holds the address). `internal/mcp/mcptest` is an invented notes server over both, for tests and `verify`.
- **`internal/connectors`**, a new package: each person's connectors in their own database (migration `20261125T171500_connectors.sql`: `connectors`, `connector_tools`, `chat_connectors`), the checks of an entry, tool names (`<connector>_<tool>`, made into a tool's name), the address rules (public HTTPS, or the person's own local server that must be local, both checked as they connect with `web.Dial`), the stdio environment, tokens from the vault, `Options.Check`, the `Pool` of sessions, what a call is offered (`ForCall`), `load_tools`, the result text, and seven routes. `internal/tools/web/guard.go` exports web_fetch's address checks for it.
- **The turn's side**, `internal/turn/connectors.go`, made like the knowledge lookups: each call that offers tools asks the pool, keeps the connector tools on the turn, and runs a call through a registry of one; `toolFor`, `runPlanned`, `noteOutside` and `resumeStep` find them; the approvals screen lists them; the runner closes the pool.
- **`tools/tenant connector add | list | check | remove`**, the only way to add a connector that runs a command.
- **The screens**: Settings → Connectors (`ConnectorSettings.tsx`) and a tools menu beside the model picker (`ConnectorMenu.tsx`), with `connectors.css`, the calls in `api.ts`, a plug icon, and the words for `load_tools` in `steps.ts`. `web/dist/` is rebuilt.

## What was learned

- A local MCP server is a program run as the account Keystone runs as, which can read every tenant's folder. Letting a person set its command from the browser would let anyone who can sign in, the test tenant included, read every other person's data: fixed rule 1 would hold in the code and fail at the operating system. So a command comes from the command line only, and so does the variable its token is passed in, which could otherwise be `NODE_OPTIONS` (decision 0310). The brief's screen adds remote connectors, and shows a command connector with how to add one.
- "Local" needed to mean local. A mark that only lifted the HTTPS rule would let a token go over plain HTTP to the internet, so a server marked local must resolve to this machine or a private network, checked as it connects (decision 0311).
- What a chat has loaded can be read from its branch: a `load_tools` call with a result that is not an error. No table was needed, and an edit that goes back before a load forgets it (decision 0312).
- Offering tools must not reach the network, or a server that is down slows every turn. What a call is offered comes from what each connector last listed; only one that has never listed is reached at offer time, and not again for a minute after a failure (decision 0313).
- The test binary can be its own stdio server: `TestMain` calls `mcptest.ServeIfAsked`, and a connector runs `os.Executable()` with a variable set. The same works for the verify binary, from an `init` in its new file.
- A token reaches a server and can come back in anything it sends. It is taken out of results, errors and a command's standard error before Keystone keeps them; the browser check and the `no keys` surface found none left.

The item's proof:

- **A test MCP server's tools are listed, loaded on demand and called.** In `go test ./internal/turn`, over HTTP and over stdio, and in `calls recorded` on the real server: the first model call is offered the server's tools by name with empty schemas and `load_tools`; `load_tools` loads two; the next calls are offered those two whole and the rest by name; the search runs and is marked as outside content; every call is in the audit log, with no token.
- **A disabled connector's tools are absent.** A second connector, switched off, has no tool in any call, and its server is never reached; a call the model makes to one of its tools anyway is answered as a tool that does not exist. A connector switched off for one chat offers nothing there and still offers in another.
- **A connector's changing tool asks.** The server's `add`, which does not say it only reads, asks, and runs once approved; set to always, it still asks with the reason `outside` after the connector's search.
- From the command line: a stdio connector whose command was a throwaway build of the test server was added with `tenant connector add`, reached, and listed five tools.
- In a browser, against a server built from this branch on port 7981 with a data folder inside the worktree (removed afterwards), signed in as the test tenant with the fixture's password, and the test server served over HTTP on port 7982 asking for an invented token: the screen listed the stdio connector as added from the command line; the add form refused the HTTP address until it was marked as the person's own server, then added it, stored its token, reached it and listed five tools. The tools menu on the new chat screen switched the stdio connector off, and the chat the first message made had it off. The recorded connector turn drew "Loaded notes_search, notes_add", the search with its marked result, and an approval card naming the Invented notes connector's add, asking because the chat read outside content; approved, it ran and the reply finished. The Approvals screen listed the `notes_` tools. The menu and the screen at phone width, in dark. The console's errors were the sign-in probe's 401 and the refused add's 400. Both servers were stopped.

Not run: `go run ./tools/rebuild`, the race detector (it needs cgo, which this machine's Go does not have), any system but Windows, a real MCP server, a stdio server started through `npx` or another package runner, and OAuth.
