# Models 006, 2026-11-24

Item provisional: P3-06, the Chat Completions adapter. Built and proven on recorded exchanges. The live checks wait on the owner.

## What was done

- A new package, `internal/adapters/chatcompletions`: a `seam.Provider` for any endpoint that speaks the OpenAI-style Chat Completions format. Standard library only. It sends one streamed request, reads the reply as server-sent events, and turns text, reasoning and tool calls into seam events.
- Errors are mapped to the seam's seven kinds from the HTTP status and the endpoint's own words. A retryable failure is sent again with a growing wait, but only while nothing has reached the caller.
- A new field in the registry entry, `ca_cert`: one certificate authority an entry trusts for its own endpoint, as PEM text or a file path. `models.Check` refuses it where it makes no sense. Nothing turns certificate checks off, and a test fails if the adapter's code names the switch.
- The key is the builder's `key` argument. No key, no `Authorization` header. The key is taken out of every message, including an endpoint's reason that repeats it.
- An entry classed `local` is called without the environment's proxy. A redirect is not followed.
- The builder, in a file of its own: `internal/adapters/chatcompletions.go`. `adapters.ChatCompletions(reg)` returns a `Set` holding this adapter alone, the way `adapters.Fake` does. `adapters.ChatCompletionsOptions(reg)` reads the six settings.
- Six settings in `settings/models.json`: `chat_completions.connect_timeout`, `response_timeout`, `idle_timeout`, `max_attempts`, `retry_wait` and `retry_wait_max`.
- `fixtures/chat-completions/`: five recorded exchanges, covering Ollama, OpenRouter, LiteLLM and the gateway, and `errors.json`, with fifteen refusals and three errors that arrive inside a reply.
- Four more refused entries in `fixtures/models/refused.json`, for `ca_cert`.
- The folder is on the `offline` check's list.
- The doc `docs/architecture/adapter-chat-completions.md`, a row in the overview, lines in `verify`'s list of parts, `internal/README.md`, `tools.md` and `models.md`, and decisions 0120, 0121 and 0122.

## What was learned

- Chat Completions tool calls do not fit the seam's one-block-at-a-time stream as they arrive. The format tags pieces with an index and lets them mix, one endpoint sends every call whole at index 0, and a call may come with no id. The adapter holds tool calls until the reply ends and sends each whole. Text and reasoning still stream. Decision 0121.
- The usage arrives after the piece that carries the finish reason, in a piece of its own with no choices. So the `stop` event cannot be sent at the finish reason. It is sent at `[DONE]`, or when the stream closes after a finish reason.
- Ollama has said `stop` for a reply that calls a tool. The stop reason is read from whether a call arrived, and the finish reason only settles `length` and `content_filter`.
- Reasoning has two names, `reasoning_content` and `reasoning`. Both are read. Asking for reasoning has no common name at all, so `thinking_tokens` is not sent yet.
- A retry is only invisible before the first event. After it, the adapter reports and the caller decides. Decision 0122.
- The `local` class and a proxy do not go together: the class says the content stays on the home network, and a proxy is another machine. Decision 0122.
- `adapters.Open` builds a provider on every call, so each call gets a new transport. Idle connections are kept 30 seconds and then dropped. Whoever runs a turn should hold the provider for the turn.
- A test in `internal/adapters` cannot start a test server, because that folder is not on the `offline` list and should not be. The test that goes through `adapters.Open` to a server is in the adapter's own folder, as an outside test package.
- `docs` fails as soon as a folder holds Go code without a doc, so the doc and its `componentDocs` line went into the build commit, and the decisions, journal and status into the one after.
- The worktree was cut from the Python `main` again. The branch `models/p3-06-chat-completions-adapter` was made from `reboot` at `2d050fe` before any work.

## What was verified

On Windows 11 with Go 1.26.0: `gofmt -l .` prints nothing, and `go run ./tools/verify` is 13 of 13.

- Each of the five recorded exchanges: the body sent is the one recorded, the `Authorization` header is there only when the entry has a key, and the reply adds up to the one recorded.
- The gateway's exchange runs over TLS with an authority and a certificate made when the test runs. A call fails with no `ca_cert` and with another authority's, and is not retried. It works with the right one as PEM text and as a file.
- Every refusal in `errors.json` becomes its seam error, and all seven kinds are covered. An error inside a reply ends it without a second call.
- Two busy answers and then a reply: three calls, one stream. An endpoint that stays busy: three calls, `overloaded`. A refused key: one call.
- A reply that breaks off, an endpoint that is not there, and a reply that goes quiet are `unavailable`. Cancelling returns the context's error with nothing sent after it. A receiver's error ends the call.
- An endpoint that repeats the key in a refusal, and in an error inside a reply, does not get it into the error or the events.
- A model added to a tenant's registry with its key in the vault is opened through `adapters.ChatCompletions` and answers. The key at the endpoint is the vault's, with a like-named environment variable set to something else.

Not run: macOS and Linux. No real endpoint: not Ollama, not OpenRouter, not LiteLLM, not the gateway.

## Provisional

The item is provisional on the live checks, which need what only the owner has:

- **The Mac mini gateway**: its address, the key it expects, and its authority's certificate as a PEM file or text. The gateway fixture is invented. Its real replies may differ in whether it reports usage, whether it sends `[DONE]`, and what it calls reasoning. The adapter handles each of those either way, and the first live call will show which.
- **OpenRouter**: a key, and the name of a model to call.
- **Ollama**, optional in the item: Ollama running on this machine with a model pulled. It needs no key, so anyone at the machine can run it.

Also left for later, and listed in the doc:

- `thinking_tokens` is not sent. Reasoning an endpoint sends is read.
- Embeddings, P6-08.
- The settings are read at their defaults. An install's own stored values are not built (see `settings.md`).
- The "no keys in output" check has no surface for this adapter. A surface would need a test server, which would put `tools/verify` on the network list. The package's own test covers the key in errors and events.

## Question for the owner

**Should a tool call's input be shown as the model writes it, for models reached through this adapter?**

Recommended: no, not yet. The adapter sends each tool call whole when the reply ends, which is the one way that is right for every endpoint. The text before the call still streams.

Assumed meanwhile: no. It holds up nothing. If the wait on a long tool input is noticed in daily use, the first call of a reply can be streamed without changing anything outside the adapter.
