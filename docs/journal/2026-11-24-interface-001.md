## What was learned

- The server's content security policy is `default-src 'self'`, which refuses inline scripts and inline style attributes. So the tokens reach the page as a stylesheet file generated at build time, the theme is set by a small script file in `public/`, and the SVG mark is coloured through classes. React still sets no `style` attribute anywhere in the app.
- `http.FileServerFS` answers 404 for a path that is not a file, so `/chats` works when reached by clicking and fails on reload. The fix belongs to `cmd/keystone/serve.go`, which this lane does not edit.
- With no API at all, `GET /api/me` returns 404 as plain text from the file server. Treating 404, 405, a non-JSON 200 and a network error all as "not ready" keeps the shell from mistaking an unbuilt server for a signed-out person.
- TypeScript 7, Vite 8 and React 19 build together cleanly on Windows with Node 24. `tsc --noEmit` passes with the bundler module resolution.
- Vite gives hashed names to the script and stylesheet, so the committed `web/dist/` changes on every source change. That is the cost decision 0005 already accepted.

## For the integrator

1. **`cmd/keystone/serve.go`, the fallback for client-side routes.** `handler()` passes every request to `http.FileServerFS(web.Files())`. It needs this instead: for a `GET` or `HEAD` whose path does not start with `/api/` and does not name a file in `web.Files()`, serve `index.html` with status 200 and `Content-Type: text/html; charset=utf-8`. Paths under `/api/` that match no route must answer 404 with a JSON body, never the page. A path that names a real file is served as now.
2. **`src/api.ts`, the real routes.** Change the four entries in `paths` and the shapes beside them. If sign-in takes a name other than `person` for the tenant id, change it in `signIn`.
3. **`tools/rebuild`, building the web app.** It does not run the web build, and it should not need Node on a machine that only builds Go. No change is needed now. The standing check in item 4 covers the drift.
4. **`tools/verify`, a standing check for `web/dist/`.** Decision 0005 asks for it: where Node is present, run `npm run build` in `web/app/` and fail if `git status --porcelain web/dist` shows a change. It was not added because this lane does not edit `tools/`.
5. **The content security policy.** The app needs nothing beyond `default-src 'self'`. Do not add `'unsafe-inline'` for scripts or styles.
6. **`.gitattributes`.** One line was added: `web/dist/** linguist-generated`.
