## What was learned

- **The composer's focus must count its sheets.** The `+` and the model's sheets are portals into the body, so a DOM check sees the focus leave the composer when a sheet opens; the composer then folded, the model's chip was hidden, and the sheet had nowhere to hand the focus back. React's focus events come up through portals, so the form's `onFocus` and `onBlur`, with a short delay before folding, see the composer and its sheets as one.
- **A tap blurs the box before its click.** On a phone a tap on a button blurs the text box at the synthesized `mousedown`; folding at once would move the button from under the finger. The 120-millisecond fold and a `mousedown` that keeps the box focused for presses on the row (and only the row's own DOM, never a sheet's boxes, whose React events come up the same way) settle it.
- **A grid with named areas would have misplaced the location lane's chip**: an element no area names is put in the next free cell. A wrapping flex box whose default is a whole line puts anything new above the box.
- **`go run ./tools/tenant test --data <folder>` ignores `--data`**: Go's flag package stops at the first argument that is not a flag, so the tenant went into the worktree's own `data` folder (ignored by git). It was moved to the scratch folder. The flag goes before `test`.
- **The test tenant's registry is empty**, so the new chat screen draws no model chip there; a chat has one, from its model route.
