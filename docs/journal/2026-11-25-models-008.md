## What was learned

- A route can be a provider. The turn already held one provider and called it for each step, so a chain that looks like a provider needed two small changes to the turn and none to how a step runs. Decision 0163.
- The budget's guard sends an error event before it returns its error. A chain that passed events straight on would show the client a failed attempt. So the chain holds a stream's start and its error back until the first block.
- A reply written by a fallback must be recorded under the fallback's name, or its thinking blocks would be sent back to a model that did not write them. The turn's own `model` stays the one asked for.
- The cap needs the cost before the call. The budget already estimates the input and knows the room kept for the reply, so the most a call could cost is one line. Decision 0161.
- `local` models are outside the cap, and the fake adapter can only be `local`. The check puts the fake provider behind an entry that names a real adapter and is marked `hosted`, through the set of builders, so the cap is proven with no endpoint and no spend.
- `docs` in `verify` wants a part's doc in the same commit as its code, so the two architecture docs went in with the build and this entry after.
- The worktree was cut from the Python `main` again. The branch was made from `reboot` at `1318039` before any work.

## What was verified

On Windows 11 with Go 1.26: `gofmt -l` prints nothing, and `go run ./tools/verify` is 16 of 16.

- Routing: each kind follows its rule and chat ignores one; a sensitive ask reaches only local and trusted models, for every kind, and has no route when there are only hosted ones; a chain refuses to be built with a model that may not read a sensitive call.
- The chain: a model that fails before its reply begins is followed by the next, each called once, and the caller sees none of the failed attempt; a reply that breaks off, an invalid request and a stopped call are not tried elsewhere; a move that cannot be recorded ends the call.
- Usage: a month sums by model and is one tenant's own; a row cannot be changed, deleted or replaced; the cap's answer at each edge, to the millionth of a dollar.
- In a turn, through the HTTP API: a failing endpoint falls back, with a started and an end entry in the audit log for each of the two calls and a usage record for each; a call over the cap is stopped and does not reach the provider; a local model is not held by the cap; a cap that does not read stops a paid call; the test tenant's calls and a title call have usage records.
- The commands: a model is added from a file and from standard input, a pasted key is refused and not repeated, and a setting is stored as the role its scope asks for.

Not run: macOS and Linux. No real endpoint was called. The fallback and the cap have run against the fake provider and stand-in providers only.
