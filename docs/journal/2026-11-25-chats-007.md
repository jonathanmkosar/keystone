## What was done

- **The order of a call** (`internal/contextbuild`). The request now carries the parts in a fixed order, `Layout`, with what changes least first: the tools sorted by name (`ByName`), the standing start, the system blocks that change rarely (attachments, summary, pinned messages, note), the earlier turns, and last recall and the current turn. Recall left the system text: its items are text blocks at the start of the current turn's first message, before the person's words, in a copy so the branch is not changed. The packing did not change. The record gained `Order` and `Cache`, and the `recall` part's place is `messages` (decision 0330).
- **Cache points on the seam** (`internal/seam`). `Request.Cache`, optional: `start`, the system blocks of the standing start, and `history`, the messages an earlier call of the chat sent too. `ValidateRequest` refuses points outside the request. The builder sets them on every chat call; nothing else does.
- **The Anthropic marks** (`internal/adapters/anthropic`). With points and `anthropic.cache_control` on, up to four marks: the end of the standing start (the last tool when it is empty), the last system block when there are blocks after the start, the end of the history, and the end of the last message. Never on a thinking block; a message the adapter leaves out is allowed for. A request with no points gets the two marks of decision 0100 (decision 0331). Five new exchanges in `fixtures/anthropic/cache.json`.
- **Cache counts from the other providers.** The Chat Completions adapter also reads `prompt_cache_hit_tokens`, the form some endpoints report instead of `prompt_tokens_details.cached_tokens`. The Responses adapter already read `cached_tokens`. Their docs now say what each provider caches by itself.
- **The fake provider.** A script's `user_text` also matches the last text block of the person's message, their own words, since recall now comes before them. Without it the recall and memory checks fell through to "anything else" whenever recall found something.
- Usage records, the audit log, `Price.CostMicros`, the spend cap and the inspector already carried and priced cache reads and writes. Nothing in them changed; the proof runs through all of them. `internal/turn` has no code change, only a new test file.
- **The proof**, `internal/turn/cache_test.go`: a stand-in Messages API that caches as the API does (by the bytes up to each mark, marks left out, a least of 1024 tokens, a look back of twenty blocks), and the shipped Anthropic adapter pointed at it.
- **A step in `verify`**, `tools/verify/cacheorder.go`, inside `context fit`.
- The write-up: `docs/architecture/caching.md`, a row in the overview, decisions 0330 and 0331, and lines in `context.md`, `adapter-anthropic.md`, `adapter-chat-completions.md`, `adapter-responses.md`, `seam.md`, `usage.md`, `knowledge-recall.md`, `turns.md`, `fake-provider.md`, `inspector.md` and `tools.md`. `docs/api/openapi.json` regenerated: 21 lines added, none changed.

## What was learned

- Most of the item was already there: the usage columns, the cost with cache prices, the inspector's cache line, the adapters' counts and two marks. What was missing was a start that stays the same. Recall sat in the system text after the standing start, and changed with every message, so every turn's history came after a changed byte and was read again at the full price. The adapter's mark on the last system block cached exactly the part that never repeated.
- Recall could only go after the history. In the person's message, before their words, it keeps the question last, reads as material because each item names its source, and in a turn of tool steps stays where it was, so each step reads the step before.
- The adapter could not have found the right places by itself once recall moved into a message: it does not know where the standing start or the current turn begins. Counts on the request say that without giving the seam one provider's notion of a mark, and without touching `seam.Block`, which the chat record stores.
- The fake provider matched the whole text of the person's message, recall and all. Moving recall broke the exact matches as soon as a store found anything; the verify checks would have shown it. Matching the last text block too keeps every old match.
- The cost of mark 4: the current message carries recall on its own turn and not later, so a turn reads all but its last turn. With no recall it reads everything. The stand-in shows both: with recall the second turn reads only the standing start, and from the third on each turn reads the turn before's history.
- The tests that passed on their first run were broken on purpose. With recall put back in the system text, the builder's tests failed through the rebuild check, the turn test with recall failed on where recall was, and the verify step reported 54 problems across the fixture models. With the adapter made to ignore the points, both turn tests failed on the marks. Each fault was taken out again.
- Windows PowerShell's `Set-Content -Encoding utf8` writes a byte order mark. It got into a Go file during one of those breaks and was taken out; the Edit tool is the way to make such a break.
