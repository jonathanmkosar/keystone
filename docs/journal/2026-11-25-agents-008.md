## What was learned

- The chain's `Moved` hook is the one moment that knows a model was refused and which comes next, before anything is sent to it. A gate asked only for paid models (the budget's) cannot stop a local model behind a refused one, so "stop instead of falling back" needed the hook, and the hook needed nothing new in `internal/routing`: an error from `Moved` already ends the call, and the turn records the refused model's call with that error (decision 0392).
- Stopping a task's round through the turn's own stop gives the pause everything for free: the context cancels the provider's call at once, and the turn already records a stopped call in the audit log and the usage records. The test's provider writes the start of a reply and then waits for its context, and both calls end within milliseconds of the route (decision 0391).
- A paused task had to stay "open" for the task limit, recovery and the scheduler's busy rule, and the `jobs` table's status has a check that SQLite cannot change in place with `job_events` hanging off it. A flag beside the stored status, shown as `paused` by the API, kept every count right with one migration line.
- Notes Keystone writes in a task's own chat must not be taken for its rounds: the runner finds a task's rounds by its request id in its work chat. They are written under a request id of their own.
- A schedule's own budget is for each run, because a run is one task with one request id; a budget for a month of runs is a different rule.

## What was verified

The item's proof:

- **The pause switch stops every running job within seconds.** In `go test ./internal/jobs` (`TestThePauseSwitchStopsEveryRunningTask`) and in `unattended spend` on the real server: two running tasks whose model calls block until cancelled are stopped by `POST /agents/pause`, which answers with nothing working and two held in under five seconds (the bound); both calls are cancelled; each task is `paused`, not failed, with a note in its chat; each cancelled call has its started and end entries and a usage record marked stopped; another person's task keeps running and their switch stays off; a task started meanwhile is held and calls nothing; after `POST /agents/resume` the two go on with a second round sent with `agents.task_unpause_text` and the held one starts, and all finish. A paused task can be stopped.
- **At the cap, unattended work falls back or stops and says so.** With the cap at nothing and a local model in the chain, a task finishes with the local model's reply, its chat says "So house-small, a local model, wrote the reply in place of paid-large.", its note in the chat it was started from says which model wrote its work, and its audit log holds the refused call (`refused`, `spend_cap`, the cap's reason) and the local one. With `agents.unattended_fallback` off it stops with `spend_cap`, says why in both chats, and the local model is not called. A chat of the person's own at the cap still falls back.
- **A run past its own budget stops and says so**: a task given a tenth of a cent through the route, and a scheduled run past `agents.schedule_budget_usd`, whose message says it is a scheduled task. A sub-agent stand-in registered with a cent is let through within it and refused past it, by name.
- In a browser, on a server built from this branch on port 7951 with a data folder inside the worktree (removed afterwards), as the test tenant: with every agent paused, a task started in a chat showed the bar and a held card; Resume all agents started it and its note came in; on Scheduled the bar both ways, a schedule's own budget of $0.50, held after Pause all agents, the form's budget field; General's control for the switch; phone width. The only console error was the sign-in probe's 401.

Not run: `go run ./tools/rebuild`, the race detector, any system but Windows, and a real model: every call was the fake provider's.
