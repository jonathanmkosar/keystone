# Agents 004, 2026-11-25

Item done: P8-01, background tasks. A task a person or a model starts in a chat runs as a durable job, with no browser, survives a server restart and resumes, reports where it is to the chat, can be stopped, asks for approvals as any turn does, and keeps to a budget of its own. Its result is written in the chat it was started from. The item has no owner gate; the card and the note on the screen are a first draft from the tokens until the agent mockups (P1-05).

Built in its own worktree on `agents/p8-01-background-tasks`, while backup and restore, the turn inspector and the memory pass were built in others.

## What was done

- A new package, `internal/jobs`:
  - A task is a row in `jobs`, with its events in `job_events`, from one migration, `20261125T151700_jobs.sql`.
  - `Runner.Start` makes the task's **work chat** ("Background task: …") and the row, with a request id of the task's own, and starts a goroutine under the turn runner (`turn.Runner.Go`), so closing the server stops it and waits for it.
  - The goroutine works the task in **rounds**: each round is a turn of the work chat, sent through the turn runner. A round at the step limit is followed by another (`agents.task_continue_text`); a round the stop cut short is followed by one that resumes (`agents.task_resume_text`); a reply ends the task as done; any other failure ends it with the turn's code. Up to `agents.task_max_rounds`.
  - Where a task is comes from its turns: the rounds are the work chat's turns sent under its request id. The row's progress, steps, rounds and spend are written from them for a reader.
  - When it ends, a **note** with the stop reason `task` is written in the chat it was started from, by a turn of that chat that calls no model, taken in the chat's queue.
  - `jobs.Gate`, the task's budget, asked before each paid call after the monthly cap. Spend is the sum of the usage records of the task's request id.
  - Five routes under `/chats/{id}/tasks` (list, start, read, stream, stop), and the tool `start_background_task`, which changes something, so it asks by default.
  - `Recover`, after the turn runner's: every task waiting, running, or ended without its note goes on.
- In `internal/turn`, one new file, `jobs.go` (sending a turn with no client, reading and stopping one, waiting for its news, a goroutine the runner waits for, the note, and a chat's marks), the field `Options.Gate`, and one changed line in `route.go`.
- Lines added in `internal/app` (a new file `jobs.go`, and lines in `app.go` and `tools.go`), five settings in `settings/agents.json`, the fixture `fixtures/test-tenant/turns/background-task.json`, and `docs/api/openapi.json` regenerated (additions only).
- In `verify`, a new standing check, `background tasks`, in `tools/verify/jobs.go`, with `internal/jobs` added to `componentDocs` and the `offline` list there. `verify` is 20 of 20.
- The screen: `web/app/src/Tasks.tsx` and `tasks.css` (a card for each task under way, and the note drawn as a reply of its own), calls added at the end of `api.ts`, a line in `Chat.tsx`, a branch in `layout.ts` and `Conversation.tsx`, a row in `steps.ts`. `web/dist/` is rebuilt.

## What was learned

- Turns already were durable jobs: a row, an event table a stream follows, a queue, recovery. Building tasks on them, in a chat of their own, gave the tool loop, approvals, the audit log, stop and restart for nothing, and the screen draws a task's steps with no new code (decision 0290). A second runner would have repeated all of it.
- Running the task in the chat it was started from looked simplest and is wrong: the task holds that chat's queue for as long as it runs, so the person cannot carry on talking there.
- Decision 0142 closes a cut-short turn as failed so a call is not paid for twice unasked. A task resumes with a new round on top of that, without changing it: the person asked for the work to finish (decision 0291).
- A task launders the fixed rules unless its chat's marks go with it: words written after a web page could drive a changing tool set to always in a clean work chat, and words from a sensitive page could reach a hosted model there. Both marks are carried both ways, and written while the chat's queue is held, so no turn runs before them (decision 0294).
- Appending a result to a chat from outside its queue can land between a message and its reply. Taking the queue, as a turn does, and writing the note as a turn's message, gave it a stop reason, a stream and the audit for free (decision 0292).
- Finding a task by its turn's request id, not by a table written after the turn, closes the moment in which a round's first call could escape the budget, and lets a crash between sending a round and noting it lose nothing (decision 0293). A `job_turns` table was planned and dropped for this.
- PowerShell 5.1's `Get-Content | Set-Content` rewrote two Go files in the machine's code page and broke their curly quotes; the files were repaired and the edits made with the editor after that.
