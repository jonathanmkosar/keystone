## What was done

- Five decision records, 0002 to 0006: Go and one binary, one SQLite database per tenant through modernc.org/sqlite, HTTP with JSON and server-sent events, React and Vite with the built files committed and embedded, and secrets encrypted per tenant under a master key the operating system holds. - `rebuild` has a new step: it starts the built binary on a free port, fetches the page over HTTP, and stops it.
- `verify`'s docs check now fails when a decision record is not linked from the overview.

## What was learned

- This was the first run on Windows. Before any change, `rebuild` was green and `verify` passed 8 of 8 with Go 1.26. Nothing needed fixing. The owner's question in `STATE.md` about the Windows run is answered.
- Go can only embed files at or below the folder of the file that asks, so the embed line has to live in `web/`, the interface lane's folder. Core added `web/embed.go` and the placeholder `web/dist/`. The interface lane owns both from P4-01 on.
- The mark files in `design/mark/` carry a block of content-credential metadata, about 9 KB each. The copy in `web/dist/` is the same drawing without that block, because it is served on every page load.
- Listening on port 0 and printing the real address lets `rebuild` and the tests start the server without a fixed port that might be taken.

## What was verified

On Windows 11 with Go 1.26.0: `go run ./tools/rebuild` green, with the binary serving the page over HTTP; `go run ./tools/verify` 8 of 8; `rebuild` run twice with the same snapshot. A planted decision record that the overview did not link turned `verify` red, and removing it turned it green again. No `keystone` process was left running after `rebuild`.

Not run again on Linux in this loop.
