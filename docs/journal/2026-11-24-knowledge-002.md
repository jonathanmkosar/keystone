## What was done

- A new package, `internal/knowledge/builtin`, registered as `built-in`. It implements `knowledge.Store` on tables in the tenant's own database and reaches them only through the tenant's store handle.
- One migration, `20261124T230000_knowledge_builtin.sql`: spaces and labels, pages, sources, the sources a page cites, page vectors, a change counter, and two FTS5 indexes.
- The store claims all four capabilities: `AddSource`, `CatalogMarker`, `VectorSearch` and `PageVectors`.
- Four plain functions for what the interface has no call for: `WritePage`, `RemovePage`, `AddText` and `SetLabel`.
- Settings: `built-in` joins the options of `knowledge.adapter`, and three new settings set the default search limit, the snippet length and the size of one list of pages needing a vector.
- Docs: `docs/architecture/knowledge-builtin.md`, a row in the overview and in `internal/README.md`, the `componentDocs` line in `tools/verify/main.go`, and decisions 0060, 0061 and 0062.

## What was learned

- The interface fits a second store with nothing bent. P6-01 shaped it against Waymarks, and decision 0030 named the built-in store as the first test of that. Nothing in the interface or the suite had to change.
- The label is safest when it is not a separate read. Each statement that returns content joins the spaces table, so there is no moment between reading a page and reading its label, and no label held in memory. A space with no row reads as sensitive because the join comes back empty and only the text `normal` is normal.
- The tables that hold content do not reference the spaces table. With a foreign key, a lost label row could not happen. Without one, it can, and the only effect is that the content reads as sensitive. The test damages the table both ways and reads every call.
- "Plain words" needed a choice the interface does not make: every word or any word. Recall will search with a whole message, so the store matches any word and leaves the order to bm25 (decision 0061). The chat record's search asks for every word, and that is right for a search box.
- With one database connection for each tenant, a query cannot run while another's rows are open. Every read here finishes its rows before the next statement, and a page comes back with its citations in one statement.
- The suite is a good specification. All twelve checks ran against the store, none skipped, and the code written from the doc and the suite passed without the suite having to be read around.

- **Vectors without a model.** Vector search and page vectors are proven with the suite's four-number vectors. No embedding model exists until P6-08. Until the store can be told which model is in use, `VectorsNeeded` does not list a page whose vector came from another model (decision 0062).
