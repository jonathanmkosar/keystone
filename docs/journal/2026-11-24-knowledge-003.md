## What was done

- A new package, `internal/knowledge/waymarks`, registered as `waymarks`. It implements `knowledge.Store` as an HTTP client of one Waymarks instance.
- The instance's address is a setting of the tenant. The tokens are three secrets in the tenant's vault, read by name through `Store.Secrets()`: `knowledge.waymarks.reader`, `knowledge.waymarks.intake` and `knowledge.waymarks.embedder`. The capabilities follow which of them are there (decision 0090).
- Settings: `waymarks` joins the options of `knowledge.adapter`, and five new settings hold the address, the timeout, the two default limits and the largest answer read.
- A fake Waymarks in the package's tests, served by `httptest`, which answers the nine calls the adapter makes as Waymarks' source says the real one does.
- `tools/verify`: the folder joins `networkAllowed` in `offline.go`, with the reason, and `componentDocs` in `main.go`.
- The test that every option of `knowledge.adapter` opens moved from `internal/knowledge/builtin` to this package. The built-in package keeps a test that the setting offers it and that every adapter in its own build opens.
- Docs: `docs/architecture/knowledge-waymarks.md`, a row in the overview and in `internal/README.md`, corrections to `knowledge.md`, and decisions 0090 to 0093.

## What was learned

- The API did not have to be guessed. Waymarks' source is on the owner's machine, beside this repo, and its API doc, route list, handlers and Go client were read there. Nothing was copied but the shape of the calls. No call was made to a running instance.
- Three things in `knowledge.md`'s table of how Waymarks fits were not as written. A source's record and text come back from one call, not two. The change log cannot make the marker, because it is trimmed to what the caller can read after the limit is applied, so two different catalogs can give the same newest entry (decision 0091). And storing a vector needs a grant neither planned token has, so there is a third token (decision 0090).
- Waymarks labels answers, not items. An answer about one space carries that space's label as its mark, so a page and its label are one answer, which is as good as the built-in store's join. An answer over several spaces needs the list of spaces as well, and the order of the two reads decides which way a race goes wrong. Content first, labels second, is the safe order (decision 0092).
- Waymarks answers 403, not 404, for a page in a space the grant does not reach, and a page may cite a source in such a space. Read as "unavailable", one such citation would make recall give up on the whole store. Read as "not found", recall skips it (decision 0093).
- A sensitive space is closed to a token until its grant names the space. A person who marks a space sensitive in Waymarks and forgets Keystone's tokens will see that space vanish from Keystone, with no error. That is Waymarks' rule working, and the memory screens (P6-07) should say so.
- The contract suite needed no change for a third store, and none of its checks had to be read around. A fresh Waymarks holds a page of its own, and the suite allows for it as P6-01 planned.
- The every-option test could not stay in the built-in package once a third adapter existed. A package's tests can open only the adapters in their own build.

## What was verified

On Windows 11 with Go 1.26.0, on the branch:

- `gofmt -l .` prints nothing.
- `go run ./tools/verify`: 12 of 12.
- `go test ./internal/knowledge/waymarks -run "TestContract$" -v` passes all twelve checks of the contract suite against the fake, with none skipped. The suite passes again with the reader and intake tokens, and with the reader alone.
- An instance that is closed, an address where nothing listens, an instance that takes a call and never answers, seven kinds of answer that are not Waymarks, and a token nobody issued: each gives `ErrUnavailable` on all nine calls. With the timeout set to 150ms, the nine calls to an instance that never answers all return inside the eight seconds the test allows.
- A redirect is not followed, and the server it points to is never called.
- No error holds a token, even when the instance echoes one back.
- Each call goes out under the token of its role.

Not run: macOS and Linux. Any call to a real Waymarks.

## Provisional

- **A real Waymarks.** The item's proof says "against a Waymarks test tenant". The fake is this lane's reading of the source, so a misreading would be in the adapter and in the fake alike. The live check is: start a Waymarks with nothing in it, issue three tokens with the grants in `knowledge-waymarks.md`, set `search.embedding_model` to `knowledgetest-embed` and `search.vector_size` to 4, and run the suite with a harness that seeds through Waymarks' own batch calls under an admin token. That harness is not written. It must not be part of `verify`, which runs with no network.
- **A chat finishes with Waymarks down.** There is no chat turn until P4-03. The adapter's half is proven: every call returns `ErrUnavailable` inside the timeout and nothing panics or hangs.
- **Relevance.** Scores are Waymarks' own, and its hybrid ranking is not a cosine. Recall's threshold for this adapter waits for P6-05.
