## What was learned

- The pause is simple only if nothing of the step has run when it starts. Deciding every call of a reply first means a stop or a restart during the wait leaves nothing to keep, and going on is "answer this reply's calls" from rows that already exist (decision 0222).
- A side effect run twice is the failure that matters most. Each approved call is marked used just before it runs, and a call of a tool set to always gets a row too, for the same reason.
- The plan says outside content makes side effects ask "in that turn". What a turn read is sent again with every later call of the chat, so the mark is on the chat (decision 0221). This is stricter than the plan and never weaker.
- The audit wrapper records a call's path and never its body, so the answer went into the path: two routes, approve and decline (decision 0223). No change to `internal/audit`.
- The P7-01 `approval` check sent the postcard and read the stream to its end. With asking built, that stream waits for a person, so the check would hang. It now declines while the call waits, which keeps every assertion it had and adds that the call asked and had not run.
- PowerShell's `Get-Content` reads UTF-8 as the system code page. A file written back through it lost its curly quotes and an accented letter; it was caught by the tests and mended. Edit files with the editor, not the shell.
- The `approval` check was seen to fail, with two problems, when `Decide` was changed to let `always` run after outside content, and to pass again when it was put back.
