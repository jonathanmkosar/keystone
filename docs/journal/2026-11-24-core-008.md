# Core 008, 2026-11-24

Item done: P2-05, the API shell and streaming.

## What was done

- A new package, `internal/api`. A route is a row of data, and `api.Handler` serves a list of them. Every route but the two for signing in goes through one `audit.Wrap`, whose `who` reads the session cookie and calls `signin.Resolve`. A handler is given an `api.Call`: its tenant's store, the session and the request id.
- A new package, `internal/app`: `app.Routes` is the one list of every route, `app.Handler` serves it, and `app.ReadConfig` reads the API's settings. The binary and `verify` both use it.
- Request ids on every answer, one JSON shape for every error, a limit on body size, a refusal of writes from another site, and the server's own log with keys and tokens removed.
- Server-sent events: `api.OpenStream`, `Send`, `Close`, a heartbeat, and `api.LastEventID`.
- The OpenAPI document, built from the routes by `api.Document`. It is committed at `docs/api/openapi.json`, served at `GET /api/v1/openapi.json`, and printed by `keystone openapi`.
- Seven routes of the shell's own: the people on the install, sign in, who am I, sign out, the person's audit log, the OpenAPI document, and a stream that counts.
- The session token is in a cookie the page's scripts cannot read, and in no response body.
- `keystone serve` opens the data folder, reads `secrets.keeper`, calls `Install.NewInstallKeeper`, and serves the API beside the page. It has a `--data` flag.
- The command-line client, in `cmd/keystone`: `people`, `signin`, `whoami`, `signout`, `api` and `openapi`.
- In `verify`: a route walk in `tenant isolation`, the API as a surface in `no keys in output`, and a new check, `calls recorded`. The code is in `tools/verify/routes.go`.
- Five settings in `settings/core.json`: `server.secure_cookie`, `server.max_body_bytes`, `server.stream_heartbeat`, `server.page_limit` and `signin.list_people`.
- Docs: `docs/architecture/api.md`, `cli.md` rewritten, a row in the overview, the walks in `tools.md`, and decisions 0040, 0041 and 0042.

## What was learned

- `audit.Wrap` asks `who` for the tenant and then calls the next handler with the same request, so `who` has no way to hand the store on. The shell puts a small holder in the request's context before `Wrap` runs. `who` fills it, the handler reads it, and the shell closes the store afterwards. `Resolve` is called once for each call.
- Sign-in cannot sit inside the wrapper, because the wrapper refuses a call with no session. So the routes served before sign-in are a kind of their own, "door" routes, outside the wrapper and with no store. The list is in the code and again in `verify`, and the two must agree (decision 0040).
- A path that is no route is sent through the wrapper too. A caller with no session gets 401 for every path and cannot learn which exist.
- `verify` cannot import the binary's `main` package, so the list of routes needed a package of its own for the walk to see what is served.
- Go 1.25 added `http.CrossOriginProtection` to the standard library. It refuses a write a browser says came from another site, with no token for the page to carry.
- The session token had no shape in `audit.Scrub`. It has one now, so a token that reaches a log line or an audit entry by mistake is removed.
- The audit wrapper's two refusals had a body of their own shape. They now carry the same three fields as every API error.
- `go run ./tools/rebuild` starts the binary from the repo root, so `serve` opens `data/` there. A test that runs `serve` must pass `--data`, or it makes a data folder beside the test.
