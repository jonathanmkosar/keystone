# Models 007, 2026-11-24

Item done: P3-07, the token budget.

## What was done

- A new package, `internal/budget`. `Check` counts a `seam.Request` for one registry model and refuses it with a `*TooLarge` when its input and the room kept for the reply are more than the entry's `ContextWindow`. The error says by how many tokens. `Guard` wraps a provider so the same refusal happens inside `Stream`, as one `too_long` error event, and the call is never sent.
- `budget.Counter`, an optional interface: `CountTokens(ctx, req) (int, error)`. A provider that has the method is asked for its own count, which is used with no margin. Everything else gets `Estimate` plus the margin: a provider without the method, no provider, and a count that failed.
- `InputRoom`, the number of input tokens a model has room for, for the context builder. `Tokens`, `Estimated` and `Measure` for a caller that wants the steps apart.
- `FromSettings` reads the options, and takes a function for stored values so an install's or a tenant's own can be passed in later.
- Six settings in `settings/models.json`: `budget.chars_per_token` (3), `budget.margin_percent` (15), `budget.message_tokens` (4), `budget.tool_tokens` (12), `budget.image_tokens` (1600) and `budget.ref_file_tokens` (4000).
- A new standing check, `context fit`, in `tools/verify/contextfit.go`, which makes 14.
- The doc `docs/architecture/budget.md`, a row in the overview, lines in `verify`'s list of parts, in `internal/README.md` and in `tools.md`, and decisions 0130 and 0131.

## What was learned

- The optional interface can live with its one reader. Go matches it by shape, so the adapters need not import the budget, and nothing in `internal/seam`, `internal/models` or `internal/adapters` was touched. Decision 0130.
- A failed count should not fail the call. The count is a second trip to the provider, and the estimate still protects the window when that trip does not work.
- The seam already has the kind for this refusal, `too_long`. Giving the budget's refusal that kind means routing reads Keystone's refusal and a provider's the same way.
- `docs` in `verify` fails as soon as a folder holds Go code with no doc, so the part's doc goes in the same commit as the code, not the one after.
- A request that asks for more reply than the model writes is not this package's to refuse. It keeps the output limit as the room and leaves the rest to the adapter. Decision 0131.
- The worktree was again cut from the Python `main`. The branch `models/p3-07-token-budget` was made from `reboot` at `2d050fe` before any work.

## What was verified

On Windows 11 with Go 1.26: `gofmt -l` on the new folders prints nothing, and `go run ./tools/verify` is 14 of 14.

- The estimate's arithmetic, block by block, on one request that holds every block type.
- A provider's count is used as it is; a provider with none, no provider and a failing count all give the estimate; a cancelled context comes back as itself.
- A count that fills the window exactly is accepted and one token more is refused as one over. A shorter reply limit makes room, and one above the output limit does not ask for more than the limit.
- Behind `Guard`, a call too large gives one valid error event and the provider is not called, and a call that fits goes through.
- The shipped settings load, a stored value replaces a default, and a value that is not a number or leaves nothing to divide by is refused.
- The standing check, on all six fixture entries and through the fake provider.

Not run: macOS and Linux. No provider's real count has been compared with the estimate, since no real adapter is merged.
