## What was done

- A new package, `internal/adapters/anthropic`: a `seam.Provider` that speaks the Anthropic Messages API over HTTP with the standard library and no SDK.
  - `wire.go` turns a seam request into the body of `POST {endpoint}/v1/messages`: system blocks, text, images, PDF and text files, tool calls and results, thinking with its signature, tools, the output limit, the thinking form and the cache marks.
  - `stream.go` reads the server-sent events and turns them into seam events: text, thinking, tool calls with their input in pieces, the stop reason and the four token counts. It has the adapter's own event reader.
  - `errors.go` turns a status and the provider's error type into one of the seam's kinds, and reads `retry-after` and `x-should-retry`.
  - `anthropic.go` has the options, the builder, `Stream` with its retries and backoff, and `CountTokens`.
  - `keycheck.go` has `KeyOutputs`, the adapter's surface for `verify`.
- A builder in a file of its own, `internal/adapters/anthropic.go`: `AddAnthropic(set, registry)`, `AnthropicOptions(registry)` and `Anthropic(options)`.
- Eight settings in `settings/models.json`, all under `anthropic.`: the version header, the retries and their two waits, the two timeouts, the cache marks, and the models that take thinking as a budget.
- `fixtures/anthropic/`: 35 exchanges in five files, each with what Keystone asks, the body the adapter must send, what the endpoint answers and what Keystone must see, and a README.
- In `verify`: the folder on the `offline` list, a surface in `no keys in output` (`tools/verify/anthropic.go`), and the doc's line in the list of parts.
- The doc `docs/architecture/adapter-anthropic.md`, a row in the overview, a line in `internal/README.md`, a paragraph in `tools.md`, and decisions 0100, 0101 and 0102.

## What was learned

- The Messages API has two forms of thinking and a model takes only one. Current models take adaptive thinking and refuse a budget. Older ones take only a budget. The seam's `thinking_tokens` fits the old form and means only "think" for the new one. The form is chosen by a setting that lists model names, which is a stopgap for a field on the registry entry. Decision 0101.
- The seam has no cache marker, and the item asks for cache control. The adapter places two marks itself: the end of the system blocks and the end of the last message. Decision 0100.
- A call can be retried without anyone noticing only until the first event is passed on. After that the receiver holds part of a reply. Decision 0102.
- Go's HTTP client drops `Authorization` when a redirect leaves the host, and would send `x-api-key` on. The adapter follows no redirect.
- `%#v` prints the unexported fields of a struct and cannot be stopped by a method on the field's type. The key is held as a function, which prints as an address.
- The API's input count already leaves out cached tokens, so the seam's four counts are the API's four with nothing subtracted. The other two adapters will have to subtract.
- The API has no error type for a prompt that does not fit. It is an `invalid_request_error` with a message, so the adapter reads the message for a few phrases. This is the weakest part of the error table.
- Folding a `redacted_thinking` block into the seam's one thinking block needed somewhere to keep its data. It goes in the signature behind `redacted:`.
- A test in `internal/adapters` that started a server would have put that folder on the `offline` list, and two lanes adding the same line to that map is a duplicate key, which does not compile. The call tests stay in the adapter's own folder, and `verify`'s surface uses stand-ins that open no connection.
- The worktree for this loop was again cut from the Python `main`. The branch was made from `reboot` at `2d050fe` before any work.

## What was verified

On Windows 11 with Go 1.26.0: `gofmt -l .` prints nothing, and `go run ./tools/verify` is 13 of 13, once for each commit.

- All 35 exchanges replay through a server on this machine. The body sent matches the fixture's, the headers are right, every event passes the seam's own rules, and the reply or the error matches.
- Every error kind is reached. A rate limit is waited out for the time the provider asked. A provider that stays busy is tried three times with waits of 500ms and 1s. A wait of an hour is not waited.
- A cancelled call returns the context's error. A receiver that goes away ends the call. A stream that goes quiet is given up and the text that arrived is kept.
- The key is in no error, no event and no printing of the provider, here and in `verify`.
- An entry that names the adapter opens through `adapters.Open` once the builder is in the set.

Not run: macOS and Linux. **No call has been made to the real API, to Ollama or to LiteLLM.** The exchanges were written by hand from the published format, not captured. They prove the adapter does what the fixtures say. They do not prove the fixtures are what the API does.

## Questions for the owner

**Should the registry entry say which form of thinking a model takes?**

Recommended: yes, a `thinking` field with `adaptive` and `budget`, left out for adaptive. It is a fact about one model, and a list of names in an install setting is a blunt way to hold it.

Assumed meanwhile: the setting `anthropic.budget_thinking_models`, whose default names the older model families. Current models need nothing set. It holds up nothing built.

**Should a person's thinking setting be a depth, low to high, and not a number of tokens?**

Recommended: decide it with the chat screen's thinking control (P4-04). Current Anthropic models take a depth, called effort, and ignore a token budget. The seam has only the number.

Assumed meanwhile: `thinking_tokens` above zero means "think", and the model decides how much. It holds up nothing built.
