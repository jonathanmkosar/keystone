## What was learned

- "Never blocks a turn" settles the shape: the summary is made beside the turn and used from the next call, so it has to be made before it is needed. A trigger share above a keep share does that, and the gap between them is what keeps a chat from being summarised at every turn (decisions 0230, 0232).
- In a tree of messages two ids are a whole range: the path down to the last message is one branch. But the ids alone are not enough to send a summary safely, because the turn builds a branch's messages differently for different models. The summary is checked against the call's own first messages before it is used (decision 0231).
- A pinned message lives inside a turn, and the builder decides which turns go only while it packs. Holding the pin's room first and giving it back when its turn is sent is the one order that never sends it twice and never leaves it out (decision 0233).
- Shares that add up to more than the open room could leave a summary unsent after its turns were already counted as summarised. The builder packs again as if the summary covered nothing when that happens, and a test drives it there.
- The P5-01 test of a long chat counted exactly two model calls under the turn's request id. The summary job adds its own calls under the same id, beside the turn. That test is the test of the note, so it now switches compaction off; the new tests have it on.
- The new tests and the new check step passed on their first run, so each was broken on purpose and seen to fail: a sensitive summary given to any call, a summary that covers nothing, a summary never marked sensitive, and pins never sent. Each was caught, and each fault was taken out again.
