## What was learned

- The brief named the tool `search_past_chats`. Replacing `search_chats` would have meant changing the `calls recorded` check, which asserts the recorded task calls `search_chats` and may only gain lines, and breaking the screen's step words, stored policies and every chat whose history calls it. Extending it under its own name was the change that broke nothing, and the brief allowed it.
- `search_chats` and `read_chat` gave a held chat to any model until now; the tool loop's journal (agents 001) left it for recall to mark chats, and recall does. The knowledge lookups had already solved the same problem for the same reason, so the past-chat tools are made the same way, for the least of the call's route, kept on the turn, and found by `lookup`. That needed three added lines in `lookups.go` and none in `internal/tools`, which P7-04 is changing.
- A held chat's content in a tool result stays in the asking chat for good, so giving it to a model that may read it must hold the asking chat, as a sensitive lookup does. The check found that a fault here leaks on the very next call.
- A job after every turn would have put a model call under the turn's request id while other checks count those calls. Waiting for the chat to rest (two minutes by default) solved that and is the better behaviour anyway: a recap of where a chat ended, not of its middle. The tests and the check set the wait to 0s for the test tenant.
- An FTS5 table does not go with its chat by itself. Triggers on `chat_recaps` keep the index in step, and a row deleted by `ON DELETE CASCADE` fires them; a test proves the search row goes with the chat.
- Every new test passed on its first run, so faults were put in by hand and each was caught, then taken out: the per-call tools always made for a model that may read sensitive content (both rule 3 tests in `internal/turn` and the `past chats` check, which printed the leaked recap and the hosted request that held it), a held chat's recap kept as not sensitive, the job never started, `MayShow` letting everything through, and a newer recap taking back the sensitive mark.
