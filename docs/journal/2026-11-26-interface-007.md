# Interface 007, 2026-11-26

Item provisional: P10-04, share links. The server side, the doors, the rules and the proof are complete; the screens are provisional on the mockups, which draw only the Share button.

Built in its own worktree, on the branch `interface/p10-04-share`, cut from `reboot` at c91b356, and pushed after every commit.

## What was done

- **The rules**, a new package `internal/share`, a guard of fixed rules 1 and 3 that reaches no setting (so it imports neither `internal/chat`, `internal/api` nor `internal/uploads`, which do; it reads the record with its own queries). A link is a row in `share_links` (migration `20261126T004100_share_links.sql`), gone with its chat. Its token is `ksh_<tenant>_<64 hex>`, kept only as its SHA-256 and shown once. `Find(install, token)` reads the tenant from the token, opens that one store, and looks for the hash there (decision 0470). `Usable` refuses a link turned off or expired (410) and one whose chat is now held or incognito (403); `Create` refuses a held, incognito or empty chat and a person past `share.max_links` (decision 0473). `Read` builds the view: live (the current branch when opened) or snapshot (the branch up to the message that was last when the link was made, kept as one id; decision 0471); words, images by id, file names, tool steps by name and whether they failed, artifacts as source, Keystone's end notes; never thinking, a tool's input or result, or anything outside the chat (decision 0472).
- **The routes**, a new package `internal/shareapi`: make a link, a chat's links, all links, turn one off, inside the audit wrapper; and two door routes, the view and an image of it. The doors are given no store, read no cookie and set none; every call that finds a link is written in its tenant's audit log under the route's pattern with `share:<link id>` as the actor, and a view that cannot be recorded is not served. Images only of the view, only uploads known as images, under `default-src 'none'; sandbox`. `docs/api/openapi.json` regenerated.
- **The token stays out of the logs**: one line in `audit.Scrub` for its shape, so the server's log line that holds the path holds `[removed]`; the door names the token as a secret to `audit.Append` too.
- **Settings**: a new `settings/share.json`, lane `share`: `share.link_lifetime` (720h, tenant; 0s never expires), `share.max_links` (50, tenant-admin; 0 makes no new link), `share.images` (true, tenant), `share.artifacts` (true, tenant), `share.default_view` (live, tenant).
- **The screens**, provisional: the Share button in the chat's header and its popover (make a link as the chat is when opened or as it is now, copy it once, this chat's links with Turn off); Settings → Shared links; the shared page at `/share/<token>`, drawn by `main.tsx` before anything asks who is signed in, reading with `credentials: "omit"`, text only.
- **The proof**: tests in both packages; a new standing check, `share`; the two doors on the door list; a share probe in the tenant isolation walk. `verify` is 32 of 32.
- The write-up: `docs/architecture/share.md` with its `componentDocs` lines (an `init` in `tools/verify/share.go`) and overview row, decisions 0470 to 0473, and a paragraph each in `api.md`, `web.md` and `tools.md`, and two rows in `internal/README.md`.

## What was learned

- **An install setting cannot be set for one tenant**, so a test of the most open links cannot set an install-scoped `share.max_links`; and no install value an admin changed is stored anywhere yet. It is a tenant-admin setting instead, which the admin sets for a person and a person cannot raise.
- **A guard may not import the chat package**: `internal/chat` reaches the registry through `DefaultLimits`. The guard walks the branch with the same recursive query `chat.Path` uses, and reads the artifact's chat with one query before asking `shareapi` for the content.
- **A TypeScript type guard to one member of a union written as `kind: "text" | "note"`** narrows to `never`; the union needs a member per kind.
- **A test of a copied row must not reuse the row's id**: tenant two could then "turn off" its own copy, which the first draft of the probe read as a cross-tenant revoke.
- Tests that passed at once were broken on purpose: with the revoked case taken out of `Usable`, the `share` check failed with the revoked link's whole view in its message.
