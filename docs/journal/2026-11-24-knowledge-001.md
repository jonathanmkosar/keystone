# Knowledge 001, 2026-11-24

Item done: P6-01, the knowledge store interface.

The lane's session built and committed the code and `docs/architecture/knowledge.md` in its own worktree and then stopped. The row in the overview, decisions 0030 and 0031 and this entry were written by the integrator at the merge, from the item's plan and the doc.

## What was done

- A new package, `internal/knowledge`: the `Store` interface, plain data types, capability flags, the `none` adapter, and a registry where an adapter registers by name. Standard library only.
- `internal/knowledge/knowledgetest`: the contract suite every adapter's tests call.
- One setting, `knowledge.adapter`, default `none`, in a new lane file, `settings/knowledge.json`.
- Docs: `docs/architecture/knowledge.md`, a row in the overview, and decisions 0030 and 0031.

## What was learned

- Having no store is an adapter and not a special case. A caller that gets `none` sees an empty store with every flag off (decision 0030).
- A label that is not `normal` reads as sensitive, so an adapter that forgets a label sends content to fewer models and not more (decision 0031).
- The interface was shaped against Waymarks, so the Waymarks adapter should be a translation. The table is at the end of `knowledge.md`.
- The doc linked two decision records that had not been written when the session stopped. `verify` checks that every record is linked from the overview. It does not check that every link in a doc leads somewhere. That is worth adding to the `docs` check.
