## What was done

- **A package of its own.** `internal/styles` keeps a person's own styles (a name and instructions on tone and format) and gives each chat its style. It reads no setting and does not import the chat record, so it is a guard of fixed rule 1 in `fixed rules`, as `internal/projects` is.
- **The built-in styles** are one install setting, `styles.builtin`, a JSON list of `{id, name, instructions}`, checked by `ParseBuiltIn`: Normal (no instructions, so it sends nothing), Concise, Explanatory and Formal, in invented words (decision 0450). They are not rows; a person cannot change them, and makes their own instead.
- **The record** (migration `20261125T235300_styles.sql`): `styles` (the person's own, with ids of sixteen hexadecimal characters, which no built-in id may be) and `chat_styles` (a chat's own style; the chat column refers to the tenant's own chats with `ON DELETE CASCADE`). Make, rename, change, delete; a name may not be another style's in any letter case; deleting a style takes it from its chats.
- **Which style a chat uses**: its own, else the person's default (`styles.default`, `normal` shipped, as `chats.default_model` names a model), else none. A chat's first turn keeps the default it used as its own, so changing the default reaches new chats only (decision 0451). A default that named a deleted style goes back to the shipped one.
- **Into each call** (`internal/turn/styles.go`, three added lines in `context.go`): the heading of `styles.heading` with the style's name, and its instructions, in the context builder's `style` part, which was waiting in the standing start since P5-01, last of its five parts, under the first cache point. A chat that keeps its style keeps its start byte for byte; changing it changes only that part, from the next call. The inspector already named the part.
- **What a style may change** (decision 0452): only those words. It is read after the route; `internal/styles` imports nothing of routing, the model registry, recall, the tools or the approval rule, and the check fails if it ever reaches one.
- **Eight routes**, listed in `internal/app` (one added line): `/styles`, `/styles/{id}`, `PUT /styles/{id}/default`, `GET` and `PUT /chats/{id}/style`. `docs/api/openapi.json` regenerated.
- **The screens**, provisional: a style picker between the tools menu and the model picker in both composers (a pick in a chat is sent at once; the new chat screen keeps its pick and gives it to the chat its first message makes, as the tools menu does), and Settings → Styles to make, edit, delete and make default. New files `StylePicker.tsx`, `StyleSettings.tsx`, `styleCalls.ts`, `style-presets.css`; added lines in `Settings.tsx`, and in `Chat.tsx` an import, one added line and two changed lines. `web/dist/` was built to look at it and not committed.
- **The proof**: `internal/styles/styles_test.go` (seven tests), `internal/turn/styles_test.go` (five), with the fake provider scripted to answer one invented question by what the system text holds: a sentence with no style, a bulleted list for the person's own style, a formal sentence for the shipped Formal. The check `styles` in `tools/verify/styles.go` proves the same on the real server. `verify` is 29 of 29.
- The write-up: `docs/architecture/styles.md`, decisions 0450 to 0452, a part row and three decision rows in the overview, a paragraph in `tools.md` and `context.md`, and a section in `turns.md` and `web.md`.

## What was learned

- The item was mostly joining what was there, as projects was: the slot, its place in the cache order, its line in the record and its label in the inspector all existed. The new code is the record, the routes, the choice of default and the screens.
- The fake provider's rule that the script with the most conditions wins made the proof short: one script with the question alone, and one more for each style with `system_contains`, so the style in the request decides the reply and nothing else does.
- A name that differs only in letter case reads as the same style in a picker, so it is refused; SQLite's `NOCASE` folds ASCII only, so the list's order is by bytes past ASCII. The test uses ASCII names.
- Editing a Go test file through PowerShell's `Get-Content -Raw` and `WriteAllText` turned an accented name into mojibake, since the file was read in the system's code page. The test now uses ASCII; files are edited with the editor only.
- The preview tool wants a `launch.json` in the main checkout's `.claude` folder, outside the worktree. The server was started by hand on port 7965 instead, with a data folder in the worktree, and the browser opened on its address.
