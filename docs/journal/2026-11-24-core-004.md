## What was learned

- The item says "numbered" migrations and PARALLEL.md says they are named by date and time. PARALLEL.md is the later text and exists so two lanes can add migrations at once, so files are named by date and time. Decision 0003 already said so. The cost is that a migration with an earlier name than one already applied still runs, which lanes need when they rebase.
- A store handle holds its folders as `os.Root` values, so a path such as `../other/files/x` is refused by the standard library and not by a check of ours that could be forgotten.
- A database copied from one tenant's folder to another's is refused, because each database records its tenant id and the handle compares it with the folder's.
- Adding the module moved `go.mod` from Go 1.24 to Go 1.26.0. This machine has 1.26.0. A machine with an older Go downloads the newer toolchain on first build.
- An agent worktree under `.claude/worktrees/` is a full checkout inside the repo, so `verify` and `snapshot` walked it and went red. Both now skip `.claude`, and `/.claude/worktrees/` is in `.gitignore`. That folder is tooling, not part of the repo.
- `keystone.json` keeps fields this part does not know, since the plan puts ports and a master key reference there later.

## What was verified

On Windows 11 with Go 1.26.0: `go test ./...` passes, `go run ./tools/verify` 8 of 8, and `go run ./tools/rebuild` green, run twice with the same snapshot. The tests cover the item's proof: two tenants are created, one handle cannot read the other's rows or files, a path that climbs out of the folder is refused, migrations run from an empty file and only once, and a database from another tenant is refused.
