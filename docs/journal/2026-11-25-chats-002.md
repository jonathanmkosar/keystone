## What was done

- A new package, `internal/turn`: the chat and turn routes, and the runner behind them. Twelve routes under `/api/v1/chats`, registered in `internal/app`.
- The contract was committed first, with every route answering 501, so the chat screen (P4-04) could be built against it at the same time: the route types, `docs/architecture/turns.md` and `docs/api/openapi.json`. No shape changed in the build that followed, and the OpenAPI file is the same in both commits.
- Chats in the API: list, make, read with the current branch, rename and star, delete, search, and step to a branch. They are thin handlers over `internal/chat`, which was not edited.
- Turns: `POST /chats/{id}/turns` sends a message and streams the reply as server-sent events. `GET .../turns/{turn}/events` is the same stream from the start or from after `Last-Event-ID`. `POST .../stop` stops a turn. `GET /chats/{id}/model` says which model a chat will use.
- A turn is a row in the tenant's database, and so is each event it streams. One migration, `20261125T030000_turns.sql`: `turns`, `turn_events` and `turn_messages`.
- The runner works each chat's turns one at a time, in a goroutine with a store of its own. It appends the person's message, builds the request from the current branch, opens the model with `adapters.Open` behind `budget.Guard`, streams the reply into the table, appends the reply to the record with its model, usage and cost, and writes the audit entries.
- The test tenant always gets `testtenant.Provider`, and its registry is never read.
- An edit and a retry are fields of the send body, and make branches as the chat record already does.
- Stop cancels the model call's context. What had streamed is appended as a message with the stop reason `stopped`.
- When the handler is made, a turn that was queued runs, and a turn that was running is closed as `interrupted` with its streamed text kept.
- Titles: after a reply, while the chat has none. A model the settings name writes it. The fake writes none, so its title is the first words of the message.
- Seventeen settings in `settings/chats.json`. The registry's chats lane now holds twenty.
- `app.Config` gained `Turns`, `Adapters` and `app.Open`, which returns the handler and a function that stops the runner.
- In `verify`: the route walks cover the new routes with no change, because they read `app.Routes`. `calls recorded` gained `tools/verify/turns.go`, which sends a message as the test tenant and reads the audit log for the model call.
- The doc `docs/architecture/turns.md`, a row in the overview, a line in `componentDocs`, a line in the `offline` check's list, and decisions 0140 to 0144.

## What was learned

- The shell closes a call's store when the call ends, and a handler is given no install. A turn outlives its call, so the runner holds the install and opens a store by the id of the store it was handed. This is the one thing in the build that touches the shell's promise, and it has its own record, 0141.
- Reading the stream from the table made three features one query: resume, replay of a finished turn, and a second reader. The first draft of the plan had an in-memory hub that sent events to subscribers. It would have needed a replay buffer and would have lost everything at a restart.
- The wake-up from the runner to a reader has to be asked for before the last look at the table, not after. Otherwise an event written between the look and the asking waits for the poll.
- The goroutine that works a chat's queue checks for the next turn and gives up its place under the same lock that a new turn takes to start one. Without that, a turn that arrives just as the goroutine leaves is never run.
- `Collector.Partial` gives what a stopped call had written, and it can hold a thinking block that never got its signature. The chat record refuses that block. The runner stores the rest.
- The record holds what happened, and a provider takes less than that. A stopped turn can leave a tool call with no result, and every provider refuses the next request. The request is built by leaving such calls out, and thinking from another model, and by joining two messages in a row from one side.
- A stopped server and a server stopped on purpose should take the same path. `Runner.Close` writes nothing, so the restart test walks the path a crash takes.
- Deleting a chat while its turn runs: the turn is stopped first. The goroutine's later writes find no row and are dropped.
- The route walks send `{}` and unknown fields to every route with `x` for each id. The new routes look up the chat before they read a body, so each answers 404 or 400 and starts no model call. A route that started work on such a call would have left more than two audit entries and failed `calls recorded`.
- The fake's catch-all script would have titled every chat with the same sentence. That is why the fake writes no title.
- A check that removes its data folder has to stop the runner first. On Windows an open database file cannot be removed. `app.Open` exists for that.

## What was verified

- `go test ./internal/turn` passes, and passed three times in a row. It uses a real HTTP server from `httptest`.

The item's proof, each a test:

- A turn streams to a client. The events arrive in order with ids from 1, the deltas join to the scripted reply, and the record, the title, the usage and the audit entries agree with the stream. The stream resumes after `Last-Event-ID`.
- Stop ends the model call. A provider that waits in the middle of a reply sees its context end. The half reply is in the record.
- A queued turn finishes after a restart. One server is stopped with a turn in its model call and a turn waiting. A second server on the same folder finishes the waiting one.

Not run: `go run ./tools/rebuild`, the binary in a browser, any system but Windows, and any real model. The race detector was not run.

| Question | Recommended, and built | Holds up |
| --- | --- | --- |
| A turn that was in the middle of its reply when the server stopped: run it again, or close it as failed with a retry? | Close it as failed, and keep the words that had streamed. Running it again pays for the call twice without being asked (decision 0142). | Nothing |
